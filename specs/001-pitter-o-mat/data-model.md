# Data Model — Pitter-o-mat Multiplayer Console

## PlayerSlot
- **Primary Keys**: `slot_id` (1-6 per session)
- **Attributes**:
  - `display_id` — physical ESP32 screen assigned for the slot
  - `spiel_led_start` / `spiel_led_end` — inclusive group indices on SpielLED strand
  - `grenz_led_left` / `grenz_led_right` — boundary group indices on GrenzLED strand
  - `active` — boolean flag indicating participation in current session
  - `joker_adjacent` — optional group index reserved when Joker enabled
- **Relationships**:
  - Links to one `PlayerProfile` (companion app) when names are available
  - Contained within a `GameSession`
- **Validation Rules**:
  - SpielLED ranges must be contiguous and non-overlapping across active slots
  - GrenzLED boundaries must form a closed ring with neighbors
- **State Transitions**:
  - `inactive` (waiting) -> `armed` (session configured) -> `playing` -> `finished`

## GameMode
- **Primary Keys**: `mode_id` (string, e.g., `lichtloser`)
- **Attributes**:
  - `min_players` / `max_players`
  - `supports_highscore` — boolean
  - `requires_joker` — boolean flag; Joker optional otherwise
  - `allowed_led_overrides` — list of segments the mode can repurpose
  - `win_animations` / `lose_animations` — enumerations of permitted effects
- **Relationships**:
  - Referenced by multiple `GameSession` instances
- **Validation Rules**:
  - `max_players` <= 6, `min_players` >= 2
  - Joker cannot be required when `supports_highscore` is false (avoid unused visual cues)

## GameSession
- **Primary Keys**: `session_id` (UUID generated by ESP32 master)
- **Attributes**:
  - `mode_id`
  - `player_count`
  - `joker_enabled`
  - `joker_color` / `joker_animation`
  - `start_timestamp` / `end_timestamp`
  - `status` — `configuring | running | completed | aborted`
- **Relationships**:
  - Contains 2-6 `PlayerSlot` entries
  - Emits telemetry events to `SessionEventLog`
- **Validation Rules**:
  - `player_count` must equal number of active `PlayerSlot` entries
  - Joker configuration must be compatible with selected `GameMode`

## HardwareNode
- **Primary Keys**: `node_id` (assigned per ESP32/Arduino)
- **Attributes**:
  - `role` — `master_esp`, `client_esp`, `arduino`
  - `firmware_version`
  - `last_seen` — heartbeat timestamp
  - `update_status` — `idle | pending | downloading | success | failed`
  - `transport` — `rs485` or `wifi`
- **Relationships**:
  - Master node tracks state for all client nodes
  - Update events persisted to `FirmwareUpdateLog`
- **Validation Rules**:
  - Clients must report same major firmware version as master after update
  - Heartbeat gap >10 seconds marks node as disconnected

## HighscoreEntry
- **Primary Keys**: composite (`mode_id`, `player_profile_id`, `rank`)
- **Attributes**:
  - `score`
  - `achieved_at` (UTC timestamp)
  - `duration_seconds`
  - `metadata` — optional (e.g., Joker usage)
- **Relationships**:
  - Stored under `GameMode.supports_highscore == true`
  - Player mapping resolved via companion app profile ID
- **Validation Rules**:
  - Entries sorted descending by `score`
  - Retain top N entries (configurable, default 10)

## SessionEventLog
- **Primary Keys**: (`session_id`, `sequence`)
- **Attributes**:
  - `event_type` — e.g., `encoder_turn`, `score_update`, `boundary_violation`
  - `payload` — compact binary or JSON chunk
  - `emitted_by` — `arduino` or `esp32-<id>`
  - `timestamp_ms`
- **Relationships**:
  - Append-only log associated with `GameSession`
- **Validation Rules**:
  - `sequence` increments monotonically
  - Log truncated/archived when session ends
